## 四、執行中發現的問題（重要）

**第一版重建方向錯了。** 我先只把「模型內部多一層 `Rescaling(1/255)`」加回去，訓練 40 epochs 得到 val_acc **0.5179**、四類都還預測得到 —— 明顯不是塌陷。

回頭查舊 session 的 checkpoint（`018-6-4.md`）才確認：**修正前的網路同時有 `Rescaling` 和 `BatchNorm`**。BatchNorm 的 `momentum=0.99` 移動統計量每 epoch 只更新 36 次（需約 100 次才成熟），推論時用的 `moving_mean` / `moving_var` 還停在初值附近。只修其中一個缺陷不會塌陷，兩個一起才會。

於是重建完整的修正前網路（Rescaling + BN），結果完全對上要說明的現象：

| 指標 | 修正前 | 修正後（6.4.0 基準） |
|---|---:|---:|
| 訓練 epoch | 7（早停，最佳權重回到 e1） | 23（最佳權重 e17） |
| 驗證準確率 | **0.2071** | **0.8179** |
| 預測到的類別數 | **1** | 4 |
| 每張最大機率（平均 / 最小） | 0.4028 / 0.4014 | 0.8763 / 0.3321 |

修正前 280 張驗證集全部被判成 `overcast`（sunny 0 / overcast 280 / rainy 0 / snowy 0）。

**另一個發現：原本的文字是錯的。** 原文寫「準確率剛好等於多數類別的比例」——多數類別是 `snowy`（107/280 = 0.3821），但模型挑的是數量第二少的 `overcast`（58/280 = 0.2071）。實際比多數類別**低**。這句話是推論出來的，不是量測結果，已照實改寫並在 6.4.1 末尾用一個提示框承認「這一節先前寫錯過」。
