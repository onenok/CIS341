2.2 掃描與計數

函式做什麼
list_images(label)列出某類資料夾裡所有圖檔（副檔名白名單 .jpg/.jpeg/.png/.bmp/.webp）
scan_counts(labels, index)每類的張數。關鍵設計：傳入 index 才算得出「去重後的 distinct 張數」，沒傳就只能算原始檔數。

2.3 接近重複偵測（L134–L269）

這裡用了三種指紋，缺一不可：

函式原理抓得到什麼
_md5()檔案位元組的雜湊完全相同的檔案（同一張圖下載兩次）
_ahash()縮成 8×8 灰階，記每個像素比平均值亮還是暗（64 bit）整體亮度／色彩分佈相近 → 抓「同一張圖被重新壓縮或縮放」
_dhash()縮成 9×8 灰階，記每個像素「比右邊鄰居亮還是暗」（64 bit）左右漸層結構 → 抓「同一場景、不同曝光」
為什麼 aHash 和 dHash 必須「同時」滿足才算重複 這是本專案最重要的一個防錯設計。只靠 aHash 的話，所有「整片平坦灰天」的照片會被判定成同一張 —— 因為它們都是上半部亮、下半部暗，8×8 平均值一比就全中。那會把 overcast 這個類別直接吃掉九成。

所以 build_index() 的規則是：md5 完全相同 或（aHash 差距 ≤ 6 bit 且 dHash 差距 ≤ 6 bit）才算同一群。dHash 帶有「左到右的結構」，平坦天空的照片在結構上其實各不相同（雲的分佈位置不同），所以不會被誤併。

hash_all() 還有一層 mtime 快取：每張圖的指紋存在 datasets/review-sheets/cache/image_hashes.json，只要檔案的修改時間沒變就直接用快取。你每次重跑 notebook 不會重新算 741 張圖的雜湊。

2.4 去重與分割（L278–L357）

函式做什麼為什麼這樣做
duplicate_summary()統計：md5 完全相同幾張、接近重複幾組、跨類別幾組、去重後剩幾張報告 2.4 節的表格來源
cross_label_groups()找出「同一張圖被歸到兩個不同類別」這是真正的標註錯誤，必須人工修。目前結果是 0 組
dedupe(index)每個接近重複群組只留一張（留檔案最大的那張，通常畫質最好）只在 DataFrame 上過濾，不刪硬碟檔案
make_split(index)分層抽樣 + 群組感知：整個重複群組一定全部落在同一邊這是防資料洩漏的關鍵。如果同一張圖的兩個版本一張在 train、一張在 val，驗證分數就是假的
評分最容易被抓的地方在這裡 如果沒有群組感知分割，741 張圖裡有 84 張是副本，隨機切的話幾乎保證會有副本跨到驗證集。模型在驗證集上「看到」訓練時看過的圖，分數會虛高。

make_split() 先把每群指派到 train 或 val，再在群組層級做分層抽樣。實測結果：跨 train/val 的重複群組 = 0。這個數字 notebook 3.1 節有印出來，可以直接給老師看。

2.5 前處理契約（L360–L419）

@dataclass(frozen=True)
class PreprocessSpec:
    name: str
    image_size: tuple[int, int]
    scale: str          # 人類可讀的說明
    fn: Callable[[Any], Any]   # 實際的縮放函式
    note: str

spec_for("scratch") → 128×128、除以 255 → [0,1]
spec_for("mobilenet_v2") → 224×224、mobilenet_v2.preprocess_input → [-1,1]

為什麼要特別寫一個 dataclass 來管這件事 兩個模型的前處理不一樣，而且錯了不會報錯、只會讓準確率悄悄掉。
· scratch CNN 把 /255 寫成模型內的 Rescaling 層 → 存的模型自帶前處理
· MobileNetV2 的 backbone 不包含縮放 → 必須在外面呼叫 preprocess_input
· EfficientNet 內部就會縮放 → 如果再手動除以 255 就是縮放兩次，直接毀掉

notebook 3.3 節有實測證明：同一個像素值 128，scratch 得到 0.502，mobilenet_v2 得到 0.004 —— 差別巨大。這個 PreprocessSpec 就是保證「訓練、驗證、Gradio 推論、影片推論」四處用的是同一套規則。

6.4 節到底做了什麼（這節是評分重點）

  1. 觀察：訓練曲線上 train accuracy 一直漲（0.743 → 0.943），但 validation loss 從第 2 epoch 起就不再改善（1.368 → 2.510）→ 兩條曲線明顯分開
  2. 改變一個因子：只關掉增強，其餘全部固定（分割、seed、架構、優化器、學習率、batch size、epoch 預算、callbacks、驗證集）
  3. 重測：兩個變體在完全相同的驗證圖片上評分
變體train accval accval loss過擬合差距
有增強0.8990.2752.281+0.624
關掉增強0.9430.2752.510+0.668

macro F1 兩者都是 0.144；131 張驗證圖中錯了 95 張。

這一節記錄的是「量到了什麼」，不是「為什麼」 關掉增強後訓練準確率更高（0.899 → 0.943）、過擬合差距更大（+0.624 → +0.668）， 但驗證準確率完全沒變（都是 0.275），macro F1 也一樣是 0.144， 131 張驗證圖錯了 95 張。

這說明「有沒有開增強」不是這個差距的來源 —— 這個否定性結論是 穩固的，因為除了增強以外所有條件都固定住了。但差距的真正成因 目前無法判定：訓練集只有 526 張且類別不均，資料量、類別分佈、模型容量都可能 有份，現有數據分不開。

所以 notebook 的 6.4 只寫觀察與重測結果，刻意不下診斷。 評分表要求的是「做一次受控調查」，這節把方法完整示範了，結論等資料齊全再寫。
